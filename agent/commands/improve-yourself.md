# improve-yourself

パーソナルAIパートナーチームの自己改善を行ってください。

## 確認対象ファイル

実行時に以下のファイルのすべてを読み込むこと。

`~/workspace/dotfiles/agent/`
- `opencode.jsonc`: opencodeの設定ファイル
- `AGENTS.md`: 全エージェントの役割定義
- `agents/*.body.md`: 各エージェントの役割定義
- `agents/*/*.frontmatter.md`: 各エージェントのメタデータ
- `commands/*.md`: 頻繁に利用するプロンプト
- `skills/*.md`: エージェントのスキル
- `logs/friction.md`: 未処理の摩擦ログ（初回実行時は存在しない）
- `logs/improve.md`: 当作業により適用した改善ログ（初回実行時は存在しない）

※ 注意事項

`agents/*/dist/*.md`ファイルは、 `agents/*.body.md` と `agents/*/*.frontmatter.md` を連結して生成されたビルドファイルです。
改善の際には生成物を直接編集せず、 `agents/*.body.md` と `agents/*/*.frontmatter.md` を改修するようにしてください。

## 業務フロー

1. 確認対象を読み込む。
2. 確認対象ファイルを精査し、以下の観点で分析を行う。
    - 改善ログに記載の内容が再発していないか
    - 摩擦ログに記載の内容に要改善と思われるログはあるか
3. 分析結果をもとに、摩擦ログの内容を`要改善` | `改善不要` | `様子見`に分類する。
4. `要改善`の摩擦についてはユーザーに改善提案を行い、返答に応じてファイル編集を行う。
5. ファイルのクリーニングを行う。
    - 3で改善ログへの書き込みから30日以上再発していない（=摩擦ログに同事象が発生していない）ログについては、改善ログから削除する。
    - 4で`改善不要`としたログおよび4でユーザーから`改善不要`と言われた事象については、摩擦ログから関連記録を削除する。
    - 4で解決策を講じたものについては、摩擦ログから関連記録を削除し、改善ログにその内容を記録する。
6. 完了報告及び、利用ツールに応じて agent 定義ファイルの再ビルドを依頼するようユーザーに返答する。

## 分析と設計原則

- **構造的パターンの抽出（局所最適の禁止）**
    - 単発の特殊なミスに対して個別具体的なルール（「～の時は～しない」の羅列）を追加しない。
    - 複数のログに共通する**根本原因（ルーティング基準の曖昧さ、責務の重複、承認粒度のズレ）**を抽象化して簡潔な原則に落とし込む。
- **1-IN, 1-OUT**
    - プロンプトが長くなるほどLLMの指示遵守率は低下する。
    - 新しいルールを追加する場合は、**既存の冗長な表現・形骸化したルール・重複記述の削除や統合**をセットで提案し、全体の行数を現状維持～削減することを目指す。
- **適切な配置レイヤーの選定**
    - 全員が守るべき安全・連携ルール -> `AGENTS.md`
    - 振り分け・確認タイミング・応答テンポ -> `agents/chief.body.md`
    - 特定の専門作業の質 -> 該当するサブエージェントの`agents/*.body.md`ファイル
    - 特定環境・特定ツールの固有知識 -> プロンプト本体ではなく別ファイル等への外部化を提案
- **構成変更の検討**
    - 特定のエージェントがほとんど呼ばれていない、または逆に常に直列で呼ばれてオーバーヘッドになっている場合、役割の統廃合や起動条件の変更も提案する。
    - AIパートナーチーム内での対応改善ループが回せていない場合にもサブエージェントの追加・削減や役割変更を提案する。
- **勝手な上書きの禁止**
    - まずは**提案（diff出力）のみ**を行い、ユーザーの承認を得てから実際の編集を行う。
