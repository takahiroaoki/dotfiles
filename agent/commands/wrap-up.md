# wrap-up

本セッションのやり取りを振り返り、AIパートナーチームの改善に繋がる「摩擦」を抽出し、`~/dotfiles/agent/logs/frictions/` に保存する。

## 抽出観点

- ユーザーが前提・方針・設計の誤りを訂正した
- ユーザーが同じ意図を言い直した、または出力形式・粒度をやり直させた
- ユーザーへの確認不足による手戻り、または過剰確認・重複調査によるテンポ低下があった
- ルーティング判断の誤りや、サブエージェントとの無駄な往復があった
- ツール・権限・設定の制約でつまずいた、または回り道をした

※ サブエージェントの役割に沿った健全な検証・修正・改善ループは摩擦に含めない。

## 業務フロー

1. 本セッションのやり取り全体（およびユーザーから渡された補足指示）を振り返り、該当する摩擦を洗い出す。
2. 該当する摩擦がない場合はファイルを作成せず、その旨を簡潔に報告して終了する。
3. `git -C ~/dotfiles rev-parse HEAD` を実行し、現在の資材断面（コミットハッシュ）を取得する。
4. `~/dotfiles/agent/logs/frictions/YYYYMMDD-<slug>.md` を新規作成し、所定フォーマットで保存する（`<slug>` はセッション内容を表す短い英小文字・ハイフン区切り。同名ファイルがすでに存在する場合は末尾に `-2` 等を付けて重複を避ける）。
5. 作成したファイルパスと記録した事象の要約を簡潔に報告する。

## 出力フォーマット

```markdown
# friction

- 記録日: YYYY-MM-DD
- 資材断面: `<git -C ~/dotfiles rev-parse HEAD の結果>`

## 事象一覧

- **[${カテゴリ（品質不足 | ルーティング | 確認不足 | 過剰確認 | 出力ずれ | 制約・環境）}]**
  - 事象: ${何が起きたか1行で}
  - 原因と対策案: ${どのプロンプトやルール・環境をどう改善すべきか1行で}
```

## 注意事項

- 無理に1件にまとめず、独立した論点ごとに分けて記録する。
- **個人情報や機微情報、高換金性情報は絶対に含めない**こと。
